## Учебный пример реализации простого CI/CD-конвейера через Jenkins с деплоем в уже существующий кластер k3s через Helm

### Использованы примеры клиента и сервера из интернета

Присутствует общение между сервером и клиентом (клиент может получить статус от сервера в виде json данных)

### Написаны отдельные Dockerfile для клиента и сервера, находятся вместе с их файлами в отдельных папках

### Реализован декларативный пайплайн через Jenkins и его Jenkinsfile

Сначала планировал развернуть Jenkins внутри контейнера и настроить пайплайн из него, но уперся в проблемы доступа Jenkins к отдельным составляющим kubernetes конкретно в моей системе. 

Попытавшись их решить и перепробовав различные способы, я не добился результата и решил перейти на нативную установку Jenkins на машину, а не через контейнер. Всё же это учебный проект и здесь это допустимо.

Сборка запускается автоматически сразу после изменений в репозитории, реализовано это через WebHook и сервис webhookrelay.com для доступа к плагину Jenkins

Пайплайн параллельно собирает образы клиента и сервера, пушит образы с указанием номера сборки в Docker Hub

Обновляет Helm-релиз во внутреннем кластере k3s, подставляя новый тег образа. Все изменения и текущие настройки в кластере я наблюдаю через Lens, в котором подключен тот же кластер

### В папке charts подготовлены отдельные Helm-чарты для клиента и сервера, в основном они похожи, но у клиента еще есть файл ingress.yaml, он необходим для Traefik (встроенный Ingress-контроллер k3s). 
Благодаря этому я могу удобно открывать клиентскую часть в браузере и просто перезагружать ее после пересборки пайплайна, и никакие ip адреса внутри не меняются.

### Развернут кластер k3s с одной нодой (и мастер и воркер). Helm полноценно работает и видит кластер. 

### Выполнены все критерии приёмки:
✅ Jenkins‑пайплайн успешно запускается по Git‑событию.
✅ Образы клиента и сервера собираются и тегируются.
✅ Helm‑чарты позволяют управлять версиями через values.yaml.
✅ Обновление релиза в k3s происходит без простоя - rolling update.
✅ Клиент и сервер взаимодействуют: форма отправляет запрос, сервер возвращает статус, статус отображается в форме.
